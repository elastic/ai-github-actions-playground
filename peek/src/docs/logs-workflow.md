# Logs

Open Logs from the sidebar to explore log data with a query-visible workflow: every filter and search action updates the ES|QL editor.

Use the **Lines / Chart / Patterns** toggle to switch analysis modes while keeping a single visible ES|QL query source of truth.

Use the **Search logs** input for free text. Enter plain text to generate `message : "..."`, or wrap the text in quotes to generate `MATCH_PHRASE(message, "...")`.

Use filter chips to review and remove active clauses. Chips, search text, and query editor all contribute to the same ES|QL query.

The timeline above results is always visible. Anomaly buckets are highlighted; click a highlighted bucket to append a `CHANGE_POINT` drill-in pipeline to the query editor.

Use the **Field Filters** sidebar to quickly include (`+`) or exclude (`-`) common dimensions such as `service.name` and `log.level`.

Click any table cell to add an inclusion filter for that field/value pair. Clicking a `trace.id` cell pivots to Query Lab with a trace-scoped query draft. Clicking a `message` cell opens extract controls for `DISSECT` / `GROK`; extracted fields are added to the sidebar filter list immediately.

In **Patterns** view, grouped message signatures support quick drill-in by applying quoted search text and preserving chip/search/editor sync. Use **Run CATEGORIZE patterns** to append a `CATEGORIZE(message)` aggregation query.

Edit the ES|QL directly in the editor when you need full control. Press **Search Logs** (or Ctrl/Cmd+Enter) to run the current query.

Click the **Explain Query** button in the bottom-right corner of the ES|QL editor to toggle a plain-language explanation of the current query. The explanation is generated by the configured AI provider; if no provider is set up, the panel displays a note to configure one in Settings.
